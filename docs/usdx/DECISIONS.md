# USDX Architectural Decision Records (ADRs) & Assumption Register

## 1. Context & Scope

This document captures the formal Architectural Decision Records (ADRs) established during Phase 0 foundation setup, alongside an explicit register of accepted assumptions and deferred decisions.

---

## 2. Phase 0 Architectural Decision Records (ADRs)

### ADR-01: Smart Contract Toolchain Selection
- **Status:** Approved
- **Context:** Need a fast, reliable, reproducible local development and testing toolchain for Solidity smart contracts.
- **Decision:** Select **Foundry** (`forge`, `cast`) as the primary smart-contract compilation and testing framework.
- **Rationale:** Foundry provides ultra-fast Rust-native compilation, solid unit testing in Solidity, gas profiling, and granular EVM target configuration capabilities.
- **Consequences:** All contract tests must be written in Solidity under `test/`. Contract compilation MUST enforce `evm_version = "london"`.

### ADR-02: EVM Target Compatibility for TRON (`london` EVM Version)
- **Status:** Approved
- **Context:** Modern Solidity compilers (`solc >= 0.8.20`) default to the `shanghai` EVM version, which uses the `PUSH0` instruction. The TRON Virtual Machine (TVM) does not currently support `PUSH0`.
- **Decision:** Pin `evm_version = "london"` and `solc_version = "0.8.20"` in `foundry.toml`.
- **Rationale:** Prevents generated bytecode from containing unsupported opcodes that would cause smart contract deployment failure on TRON networks.
- **Consequences:** Developers and CI pipelines must strictly respect the pinned EVM version setting.

### ADR-03: Decimals & Token Standard Selection
- **Status:** Approved
- **Context:** Stablecoins operating on TRON must conform to standard wallet and exchange expectations while maintaining accounting compatibility with major fiat stablecoins (e.g., USDT, USDC).
- **Decision:** Adopt the standard **TRC-20** standard interface with **6 decimal places**.
- **Rationale:** 6 decimals matches TRON USDT/USDC conventions and prevents rounding discrepancies during USD fiat conversions (1 cent = 10,000 units).
- **Consequences:** Off-chain systems must format amounts using 6 decimal place precision (`1 USD = 1,000,000` base units).

### ADR-04: Hard On-Chain Solvency Envariant
- **Status:** Approved
- **Context:** Minting tokens without confirmed reserves creates unbacked circulating supply and insolvency risk.
- **Decision:** The USDX core contract must enforce `totalSupply + amount <= eligibleReserves` on every mint call.
- **Rationale:** Guarantees that even if operational minter keys or off-chain backend systems are compromised, token supply cannot exceed verified on-chain reserve attestations.
- **Consequences:** The reserve attestation oracle must maintain fresh data on-chain; stale reserve data fails closed.
